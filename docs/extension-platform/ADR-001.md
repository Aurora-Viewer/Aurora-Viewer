# Aurora Extension Platform — Stage 0 findings

## Scope and repository fit

- Product target remains the official Aurora Viewer. Product-specific plugins and extensions are outside this generic platform POC.
- The POC branch is based on official `main` at commit `77c7553bb1ab10d647ef7f78184b4b3e3c7dc113`.
- The contribution is based on the official upstream tree; product-specific forks and their extensions are outside its scope.
- Existing Aurora `aurora-updater` already demonstrates bounded ZIP entry validation, symlink rejection, duplicate path checks and safe extraction. Reuse its defensive lessons, not its viewer-update package format.
- The viewer has offline demo/test infrastructure and nearby-chat handling. Any extension event adapter must be downstream of existing block/mute/privacy decisions; no IM or group chat delivery in v1.
- This POC adds a generic runtime; the native CEF media-plugin subsystem remains separate from the WebAssembly extension API.

## ADR-001 — sandbox runtime and first implementation boundary

**Decision: Wasmi 2.0.2, interpreter-only, with no WASI integration.** Wasmi 2.0.2 is the latest stable release observed on 2026-11-20, uses an MIT/Apache-2.0 license compatible with Aurora's GPL-3.0-or-later distribution, and declares Rust 1.86 MSRV (the repository pins 1.100.0). It is an interpreter rather than a native JIT, reducing platform-specific executable-memory behavior and making Windows/Linux/macOS + ARM support easier to reason about. Enable fuel metering, strict module compilation limits, instance resource limits, portable dispatch, and extra execution checks; leave all filesystem, socket and WASI interfaces absent. Pin and vet the exact dependency in `Cargo.lock`, run the project's third-party license generator, and reevaluate if performance proves inadequate.

This is not yet a claim that the sandbox works: dependency integration and adversarial runtime tests are still required. The upstream latest-release freshness (v2.0.2 published the day before this assessment, with several safety/correctness fixes) is a risk; it requires targeted testing and regular security updates. Wasmtime 51.0.0 is also current, Apache-2.0, and offers fuel/resource controls, but its native JIT is not justified for this small event-driven plugin workload before measurements.

The first code increment is a standalone `aurora-extension-runtime` crate. It validates `.ext` ZIP packages in memory and validates/instantiates WASM through Wasmi with imports and start functions disabled. It does not invoke exported guest functions, access viewer state, install files, make network requests, or expose UI. This isolates archive and module validation from renderer and login concerns.

The comparison covered the pinned Rust version, Apache/MIT licensing, interpreter vs. JIT portability, no-WASI defaults, fuel metering, module/resource limits, and observed current releases. Before shipping, validate Wasmi 2.0.2's Windows/Linux/macOS + ARM builds, CVE response and dependency footprint; do not claim sandboxing until runtime integration passes capability-escape and resource-abuse tests. Sources: [Wasmi v2.0.2 release](https://github.com/wasmi-labs/wasmi/releases/tag/v2.0.2), [Wasmi workspace manifest](https://github.com/wasmi-labs/wasmi/blob/v2.0.2/Cargo.toml), [Wasmtime v51.0.0 release](https://github.com/bytecodealliance/wasmtime/releases/tag/v51.0.0).

## Risks / open decisions

- The persistent package registry and account/grid-scoped roots are POC features. Guest-owned key/value state is now separately gated by `extension.storage` (32 keys, 8 KiB per extension); the fixed `extension.full_access` bundle excludes it. Migration, corrupt-state recovery and failed reopen recovery still need adversarial validation.
- API v1, guest lifecycle, fuel/memory limits and runtime quarantine exist; asynchronous brokers and additional capabilities remain future work.
- The nearby-chat adapter is permission-checked and sanitizes inputs; broader privacy review is still required before release.
- The manager follows Aurora Preferences/i18n conventions; manual UI validation for this POC remains pending.
- No dedicated issue was selected for this proof of concept; maintainers may track follow-up work separately.
- This contribution is intentionally a draft; human validation, cross-platform CI and maintainer review remain required before production readiness.

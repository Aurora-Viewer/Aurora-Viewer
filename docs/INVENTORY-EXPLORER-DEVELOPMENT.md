# Inventory Explorer development guide

Explorer adds a third inventory presentation to Aurora Viewer. A reviewer can start in `ui/inventory.rs`, find the `InventoryStyle::Explorer` branch, and follow it into the host, a tab, and the inventory action dispatcher. The older Aurora layout also has functions named `explorer` in `aurora.rs`. The tabbed presentation lives in the `organized*` modules. [Inventory entry point](../crates/aurora-viewer/src/ui/inventory.rs) · [Existing Aurora presentation](../crates/aurora-viewer/src/ui/inventory/aurora.rs) · [Viewer architecture](../ARCHITECTURE.md)

## Settings and ownership

Preferences → Aurora → Windows → Inventory selects Classic Window (Legacy), Aurora, or Explorer. A fresh profile defaults to Aurora. `Settings::read_values` also handles old profiles and backup restores. An explicit `inventory_style` wins. In older settings, `classic_inventory = true` selects Classic even if `inventory.organized_explorer` is true. Otherwise an enabled Explorer flag selects Explorer. A style switch suspends the Explorer host and cancels an in-progress tab drag. [Settings and migration](../crates/aurora-viewer/src/settings.rs) · [Backup restore](../crates/aurora-viewer/src/settings/backup.rs) · [Preferences UI](../crates/aurora-viewer/src/ui/options/pages/aurora.rs)

| State | Owner and lifetime |
| --- | --- |
| Location, history, query, filter, selection and scroll | Each tab owns an `ExplorerState`. Moving a tab between panes transfers that tab and its state. The host tracks temporary drag geometry and the destination slot for the dock preview. [Tab host](../crates/aurora-viewer/src/ui/inventory/organized_host.rs) · [Tab state](../crates/aurora-viewer/src/ui/inventory/organized.rs) |
| Sidebar width, pin order and groups, local placements, Home backing-folder ID, folder symbols, presentation and collapsed groups | One shared `Preferences` value per inventory root. Folder presentation and group disclosure are keyed by `Location`. Group keys use stable enum values or pin-group IDs so changing the language or renaming a pin group preserves the association. [Local model](../crates/aurora-viewer/src/ui/inventory/organized_model.rs) |
| Inventory items, folders, ownership, permissions and fetch state | The viewer's existing world inventory supplies the records. The model maps them to locations such as Home, a category, a real folder, Library or Full Tree. Full Tree navigates the underlying folder hierarchy. [World inventory](../crates/aurora-viewer/src/world/inventory) · [Location and row projection](../crates/aurora-viewer/src/ui/inventory/organized.rs) |

The account directory holds `inventory-explorer-<inventory-root-uuid>.json`. Its version 6 document contains a change UUID and the layout. The reader accepts versions 1–6 and migrates group direction for older layouts. Saving uses a file lock, checks the last on-disk change UUID and writes atomically. A conflicting writer or an unreadable layout can produce a separate `*.conflict.json` recovery copy. Failed writes retain a dirty snapshot with its original account and inventory root in an in-memory retry queue when either scope changes; revisiting that scope restores the snapshot rather than loading stale disk state. Retry throttling does not discard a snapshot or retarget it to the newly active account. A missing inventory record during a partial fetch is insufficient evidence to discard its saved placement. [Store and migration](../crates/aurora-viewer/src/ui/inventory/organized_store.rs) · [Persisted fields](../crates/aurora-viewer/src/ui/inventory/organized_model.rs)

## Large inventories

`refresh_rows` builds an ordered snapshot for the current location and query. Its inputs include inventory generation, layout ordering revision and language. Date grouping also tracks the local calendar day. Changing group disclosure reprojects visible members from the existing ordered snapshot. Selection, range operations and keyboard commands use that visible list, so collapsing a section removes its hidden rows from the active selection. Sorting and filtering still process the matching rows, and grouped views can retain both the complete ordering and the visible rows for each tab. [Snapshot and selection reconciliation](../crates/aurora-viewer/src/ui/inventory/organized.rs) · [Grouping, sorting and layout](../crates/aurora-viewer/src/ui/inventory/organized_views.rs)

A search scans locally known titles. Scoped searches check ancestry and reuse ancestry results. A scan can nominate up to 16 unknown folders for fetching, so an initial result can be incomplete. When inventory generations change during a nonempty search, the tab can reuse its snapshot for up to 250 ms. Changing the query explicitly invalidates the snapshot. Painting uses the scroll viewport to limit the cells visited in each section. Visible material tiles share a queue across panes, capped at four pending material fetches, and use a base-color swatch. Large-folder cost therefore depends on search and sort invalidations as well as visible rows. [Search](../crates/aurora-viewer/src/ui/inventory/organized.rs) · [Viewport layout](../crates/aurora-viewer/src/ui/inventory/organized_views.rs) · [Material previews](../crates/aurora-viewer/src/ui/inventory/organized_materials.rs)

## Current upstream integration

Aurora and Classic retain the native dual-panel button and independent pane selection, clipboard and editor dispatch (`InvAction::Panel`). Selecting Explorer parks those native panes without deleting their state; switching back restores the dual-panel preference. Explorer has its own tab and detached-window host rather than nesting that host inside each native pane. Aurora retains Gallery and Combination views and its thumbnail metadata handling. Native drag navigation keeps its window/search-row bounds and tab-hover delay; Explorer alone uses distance-accelerated vertical and horizontal edge scrolling. Places landmark giving remains accepted alongside inventory cargo. Parked native panes continue servicing previews, recipient pickers and pending dialogs with their original editor UUID. Find all links opens an independent native exact-filter results window while Explorer remains the selected preference; the window is not the additional-inventory toggle and does not replace the Explorer tabs. Inventory environment actions validate item/asset/subtype identity, then retain the upstream behavior of queuing a local selection under `@setenv` for display after the lock lifts.

Explorer Cut uses native relocatable and RLVa folder-removal checks both when enabling the command and immediately before updating the clipboard. The edit-availability cache tracks the immutable RLVa snapshot and active gestures as well as inventory, layout, protected folders and worn items, without rewalking a large selection on an unchanged repaint. Menus and controls use shared theme primitives; no theme-guard exemptions are added.

The port references #2520 as partial work. Full repository checks and human validation must be repeated on the integration candidate; the historical handoff results do not establish candidate readiness.
